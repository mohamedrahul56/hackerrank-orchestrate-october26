Notes:
* SECONDARY_IDENTIFIER and PRODUCT_TELEMETRY have a rule row but **no resource id prefix exists anywhere in the data** (0 resources), so they cannot occur in the main set as separate resources.
* `support_*` ids are split into SUPPORT_MESSAGE / SUPPORT_ATTACHMENT by record context (collection `ticket_attachments`, attachment log events) in the evidence, and by the applied treatment (delete vs redact) in the sample answers.
* Ids that occur **only in system_activity** (column 4 = 0 while column 3 > 0) are generic operational noise rows ('Profile cache refresh processed cache_N', 'Transactional email delivery processed email_delivery_N'): no evidence file ever shows such a record's state or owner, so they cannot produce findings.
* LEGAL_HOLD_RECORD exists only as `legal_hold_*` rows in SQL replicas / bundles; the legal retention register PDF names six users (user_08/12/17/21/24/29 = labeled samples case_08/12/17/21/24/29, **all six** of whose gold answers contain no legal-hold step), so that PDF is context, not a step source.
* `object_*` (object storage) appears once (a catalog row about an attachment belonging only to one user).
